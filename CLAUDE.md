# Project notes

## Authorship & attribution

All commits, PR titles/bodies, PR reviews, and issue/PR comments are authored
in Akash's voice, as if written by hand:

- Never add "Generated with Claude Code", session links, robot emoji, or any
  AI-attribution footer/badge to commit messages, PR bodies, or comments.
- Never add `Co-Authored-By: Claude ...` trailers to commits
  (`includeCoAuthoredBy` is disabled in `.claude/settings.json`).
- Keep the tone personal and first-person ("I added...", "I noticed..."),
  concise, and matching how a maintainer writes about their own work.
- Before the first commit in any session, set the git identity to the
  maintainer's (matching existing history):
  `git config user.name "Akash Pathak" && git config user.email "akash.pathak@grafana.com"`
  Commits must never be authored or committed as "Claude".

This applies to every Claude session on this repo, including remote/cloud
instances.

### Known limitation: hosted GitHub integration footer

The remote GitHub integration appends a `Generated by Claude Code` footer
**server-side** to PR reviews and review comments it creates — it is not part
of the text Claude submits and cannot be suppressed from a session. Updating
a PR body does NOT get the footer; creating reviews/comments DOES. Therefore:

- After posting any review or comment, fetch it back and check for the
  appended footer; never claim it is absent without verifying.
- If the footer was appended, tell Akash exactly which comments need a manual
  "Edit → remove last two lines" pass in the GitHub UI (they post under his
  account, so he can edit them).
- Prefer putting substantial write-ups in PR descriptions (footer-free via
  update) over new comments when practical.
